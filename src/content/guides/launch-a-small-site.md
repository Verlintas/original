A small site can be simple and still be responsible. This is the checklist I would use before making a site public.

## BEFORE LAUNCH

- [ ] Choose a domain you can keep.
- [ ] Decide who operates the site and how to contact them.
- [ ] Write a privacy note that matches the actual data flow.
- [ ] Add an accessibility statement or a short accessibility note.
- [ ] Publish `/.well-known/security.txt`.
- [ ] Add a 404 page and a way back to the main content.
- [ ] Check the site at 200% zoom and with a keyboard.
- [ ] Add a sitemap and `robots.txt`.
- [ ] Add RSS or JSON Feed if the site publishes updates.
- [ ] Verify that every external link works.
- [ ] Back up the source and the build.

## AFTER LAUNCH

- [ ] Check the site on a phone.
- [ ] Test the contact address.
- [ ] Test the security address.
- [ ] Add a way to report broken links or wrong content.
- [ ] Record the date and checksum of the published build.
- [ ] Decide how updates will be announced.

## GOOD DEFAULTS

- static output where possible
- no account unless it enables a real feature
- no tracking scripts
- HTTPS
- plain text or simple HTML for critical content
- stable URLs
- a public source repository
