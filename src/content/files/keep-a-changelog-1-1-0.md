A practical convention for changelogs written for humans: one entry per version, grouped change types, newest first, and a linkable release date. It is a guide, not a formal standard.

## USE

- Create a CHANGELOG.md at the repository root.
- Group changes under Added, Changed, Deprecated, Removed, Fixed, and Security.
- Keep an Unreleased section at the top.

## NOTES

- The project is MIT licensed.
- Works well with Semantic Versioning and Conventional Commits.
